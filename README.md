# xiaohongshu-pilot

> 小红书全链路智能体运营流水线：选题调研 → Gemini 写文案 → 违禁词检测 → 官方规则校验 → 去 AI 味人味化润色 → 即梦生图 → xiaohongshu-mcp 发布 → MCP 拉数据复盘优化选题的完整闭环。

## 简介

这是一个 WorkBuddy / CodeBuddy / Claude Code 技能（Skill），把「发一篇小红书笔记」这件看似简单、实则处处是坑的事，拆成七步可检查、可回退的流水线。每一步产出一个可检查的中间产物（选题报告、初稿文案、违禁词对照表、合规清单、润色稿、封面图、复盘报告），逐步给用户确认后再进下一步。

**它解决什么问题：**

- 选题靠拍脑袋 → 用竞品调研 + 爆款规律双轮驱动，选题有据可依；
- AI 写文案一股「AI 腔」→ 专门一步去 AI 味、加人味，改写幅度控制在 30% 内保留爆款结构；
- 笔记动不动被限流下架 → 内置十类违禁词库 + 官方《社区公约 2.0》规则汇编 + 发布前自检清单；
- AI 生成图片忘了声明 → 硬性要求勾选 AI 内容声明，红线级约束；
- 发完就完了 → 发布 24–48 小时后自动拉数据复盘，优化点写回选题库，形成增长闭环。

**适合谁：** 用 WorkBuddy / CodeBuddy / Claude Code 做小红书内容运营的个人创作者或小团队，尤其是 AI 赛道内容创作者。

**触发词：** 发小红书、小红书笔记、小红书选题、小红书运营、小红书复盘、xhs。

## 功能列表

- **七步闭环流水线**（SKILL.md）：服务自检 → 选题 → 写文案 → 违禁词检测 → 规则校验 → 润色 → 生图 → 发布 + 复盘，每步有明确产出物和确认点。
- **调研融合法选题**：用 xiaohongshu-mcp 的 `search_feeds`（最多点赞 + 一周内）取赛道 TOP10 笔记，`get_feed_detail` 拉详情，提炼高频选题角度、标题句式、封面风格、评论区真实痛点；叠加爆款标题公式（数字型/悬念型/身份代入型）归纳，产出 3–5 个候选选题的《选题报告》。
- **Gemini 文案生成**：经本机 New API 网关（OpenAI 兼容接口）调 Gemini，喂入选题报告 + 用户人设 + 爆款公式，输出标题（≤18 字留余量）、正文（≤900 字）、5–8 个话题标签、配图分镜建议；明确要求小红书调性（口语化、emoji 适度、有人味细节、无翻译腔）。
- **十类违禁词扫描**（references/banned-words.md）：绝对化用语、虚假承诺、诱导营销、封建迷信、权威背书、金融投资、站外导流（含 V/薇/扣1 等谐音变体）、医疗功效越界、豁免场景、AI 审核灰区；命中即给出「原文 → 改后」对照表。
- **官方规则校验**（references/compliance-rules.md）：对照《社区公约 2.0》三大板块红线、12 类违规营销玩法、账号矩阵规则、AI 内容专项打击、高危行业附加要求，逐项打勾《发布前自检清单》；规则有更新时先 WebSearch 补充再校验。
- **去 AI 味润色**：删大词（「赋能」「抓手」「总而言之」）、破工整排比，加口语短句和个人亲历细节（向用户要 1–2 个真实小细节嵌入），允许适度不完美；改写后回扫一遍违禁词。
- **即梦生图**：按 jimeng-generate 技能调用，输入配图分镜建议 + 调研所得封面风格；封面图至少出 2 版供用户挑选，图片存项目目录并记录本地绝对路径。
- **安全发布策略**：`publish_content` 首发建议 `visibility=仅自己可见`，用户在 App 检查并**手动补勾 AI 内容声明**（MCP 不支持自动勾）后转公开；支持 `schedule_at` 定时发布（1 小时–14 天）；记录标题、发布时间、feed_id 到项目 `.workbuddy/memory/` 当日日志。
- **数据复盘闭环**：发布 24–48 小时后（或用户说「复盘小红书」），用 `user_profile` + `get_feed_detail` 拉赞/藏/评/分享数据，对比预期 vs 实际，产出《复盘报告》（数据表 + 3 条可执行优化点），写回选题库。

## 工作原理与技术栈

- **技能形态**：纯提示词工程型 Skill——`SKILL.md` 定义流水线与红线，`references/` 三份文档提供词库、规则、API 速查，无脚本代码。
- **xiaohongshu-mcp 本地服务**（references/mcp-api.md，v2.5.0，xpzouying/xiaohongshu-mcp）：HTTP MCP 协议，`http://localhost:18060/mcp`；Windows 二进制（登录工具 + MCP 服务），Cookies 存 exe 同目录、登录一次长期有效；提供 13 个工具（登录、发布图文/视频、搜索、详情、评论、点赞、收藏、用户主页等）。沙盒会回收进程，必须用危险模式豁免后台启动，启动后 `curl` 验证存活。
- **New API 网关**：`http://localhost:3000/v1/models`，OpenAI 兼容接口，为文案步骤提供 Gemini 模型。
- **即梦生图**：复用 jimeng-generate 技能（同样走 New API 网关）。
- **关键硬限制**：标题 ≤20 字、正文 ≤1000 字（超限发布失败）；feed_id 与 xsec_token 成对出现缺一不可；图片用本地绝对路径最稳；视频仅本地路径且建议 <1GB。

## 安装与使用

### 安装

把本仓库目录内容复制到技能目录，文件夹名保持 `xiaohongshu-pilot`：

- WorkBuddy / CodeBuddy：`~/.workbuddy/skills/xiaohongshu-pilot/`
- Claude Code：`~/.claude/skills/xiaohongshu-pilot/`

重启会话后即可通过触发词自动匹配。

### 前置环境（第 0 步服务自检）

1. **xiaohongshu-mcp 服务**：`curl http://localhost:18060/mcp` 无响应 → 启动 `xiaohongshu-mcp-windows-amd64.exe`（沙盒环境下须 `dangerouslyDisableSandbox=true` + `run_in_background=true` 后台启动，启动后 curl 验证存活）。
2. **登录状态**：调 `check_login_status`；未登录 → 运行 `xiaohongshu-login-windows-amd64.exe` 弹出二维码请用户扫码（首次运行自动下载约 150MB 无头浏览器，保持网络畅通）。整个流程只有这一步需要用户动手。
3. **New API 网关**：`curl http://localhost:3000/v1/models` 确认有 gemini 开头的模型可用。
4. **即梦服务**：按 jimeng-generate 技能自检。

### 日常使用

直接说「发小红书」「帮我想个小红书选题」「复盘小红书」即可进入流水线。典型节奏：

1. 技能产出《选题报告》（3–5 个候选 + 爆款依据 + 推荐项），你选一个；
2. Gemini 出初稿 → 违禁词对照表 → 合规清单 → 润色稿，逐步确认；
3. 即梦出至少 2 版封面，你挑一版；
4. 发布前给你看最终文案 + 图片 + 校验清单，确认后先「仅自己可见」发布；
5. 你在 App 检查、补勾 AI 声明（笔记 → 设置 → 内容类型声明），确认后转公开；
6. 24–48 小时后说「复盘小红书」，拿到《复盘报告》。

## 注意事项

- **发布红线（不可跳过）**：发布动作前必须给用户看最终文案 + 图片 + 校验清单结果，得到确认才发；禁止多账号矩阵式发相同内容（官方红线）；禁止任何站外导流话术；AI 生成内容必须提醒用户勾选 AI 声明。
- **AI 声明是硬要求**：即梦生成的图片发布时必须勾选「笔记含 AI 合成内容」，未声明被抓判「AI 虚假人设/AI 广告营销」，限流甚至封号；MCP 不支持自动勾选，只能发布后手动补。
- **字数硬限**：标题 20 字、正文 1000 字，超了发布会失败——所以文案步骤要求 ≤18 字 / ≤900 字留余量。
- **环境强绑定**：依赖 Windows 本机的 xiaohongshu-mcp 二进制、New API 网关（127.0.0.1:3000）、jimeng-generate 技能三件套；缺一不可跑完整流水线。
- **沙盒限制**：MCP 服务在沙盒中会被回收，必须危险模式豁免后台启动。
- **违规代价**：单条违规降权（推荐流量减 80%）+ 下架，累计 3 条禁发 7–30 天，限流后恢复权重平均 45 天——合规步骤不是形式主义。
- **规则时效**：references 词库与规则整理于 2026-09-15；平台规则常更新，第 4 步校验时如有新规先 WebSearch 补充。
